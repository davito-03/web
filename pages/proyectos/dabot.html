Qué es

Dabot no es un bot de “tres comandos de moderación”. Es un producto: el mismo proceso cubre un servidor de Discord (slash commands, eventos, jobs) y un sitio público en dabot.davito.es donde el staff configura el guild con su cuenta de Discord.

Hay unos 68 cogs en runtime. main.py no carga tts; music no está en el árbol. La config viva de cada guild es JSON en SQLite (guild_configs), no YAML. El estado (tickets, economía, sesiones web, infracciones) comparte el mismo dabot.db en WAL entre el bot y la API.

Dabot is a product, not a three-command mod bot: one codebase covers a Discord server and a public dashboard at dabot.davito.es where staff signs in with Discord.

About 68 cogs at runtime. tts is skipped; music is not in the tree. Live per-guild config is JSON in SQLite (guild_configs), not YAML. Tickets, economy and web sessions share dabot.db in WAL between the bot and the API.

Docker Compose levanta dos servicios: dabot-bot (python main.py, health por /tmp/bot_alive) y dabot-api (uvicorn, health GET /healthz). Comparten volúmenes de código, configs, templates y la base. El puerto de la API solo escucha en localhost; nginx publica el dominio.

Al arrancar: .env → permisos del owner → ConfigManager → sesión aiohttp → bot.db.setup() → traductor de slash → load_extensions() → bot.start. Hay un guardia anti crash-loop (restart_state.json) y un RepairEngine si el proceso muere en bucle.

Compose runs two services: the bot (heartbeat file) and the API (/healthz). They share code, configs, templates and the database. The API binds localhost; nginx publishes the domain.

Boot: env → owner permissions → config → aiohttp → SQLite setup → slash translator → load cogs → start. Crash-loop guard plus a repair engine if it dies in a loop.

Módulos (cogs)

Cada archivo en cogs/ es una extensión de discord.py. Agrupados por lo que hacen de verdad:

Each file in cogs/ is a discord.py extension, grouped by what they actually do:

Moderación

moderation.py grupo /mod: kick, ban, timeout, warns, purge, apelaciones, CSV.

AutoMod propio

automod.py spam, flood, invites, unicode, /antilinks. Complementa reglas nativas en discord_automod.py.

Anti-raid / anti-nuke

antiraid.py lockdown por flood de joins. antinuke.py límites y whitelist contra acciones masivas.

Verificación

verification.py captcha/emoji/math. La web aporta IP/device que Discord no da al bot (alt_intel.py, proxy_detect.py).

Tickets

tickets.py panel, categorías, mensajes en SQLite, transcripts HTML. ticket_extras.py CSAT y snippets.

Niveles

leveling.py XP de texto (cooldown 60 s) y loop de voz, tarjetas Pillow, roles por nivel, leaderboard.

IA

chatbot.py pool Gemini / Groq / Cohere / OpenAI / OpenRouter / HF / Cloudflare. gemini_client.py rota claves y modelos.

Economía y juegos

economy.py casino.py games.py — por servidor, no un global único.

Voz temporal

voice.py join-to-create. Stats de tiempo en voice_stats.py.

Backups

server_backup.py y plantillas en server_templates.py, también disparables desde el panel.

Privacidad

privacy.py exportar/borrar datos. Fingerprints en privacy_crypto.py.

i18n

langs/*.json (es, en, fr, de, it, pt, ja, ko, zh). El bot traduce embeds y descripciones de slash en caliente.

El panel (dabot.davito.es)

dashboard_server.py es una API FastAPI, no un adorno. Login con Discord OAuth2 + PKCE S256, state en SQLite, cookie de sesión, CSRF en /api/*, CSP y HSTS. El staff ve canales, roles, config JSON (SQLite), infracciones, tickets, leaderboard, backups y una consola live de mensajes. /healthz y /api/status viven en routers aparte.

Rutas públicas de producto: /, /dashboard, /servers, /niveles, /normas, /verify, /premium, /cuenta. Webhooks de Stripe / Sellix / Discord para premium. Health en /healthz.

dashboard_server.py is a real FastAPI app: Discord OAuth2 + PKCE S256, SQLite state, session cookie, CSRF, CSP, HSTS. Staff gets config, infractions, tickets, backups and a live message console.

Product routes include dashboard, servers, levels, rules, verify, premium. Stripe/Sellix/Discord webhooks. /healthz for the compose healthcheck.

Sitios del código que importan

Localización transparente. En main.py se parchean Context.send e InteractionResponse.send_message para traducir content, embeds y views según el idioma del guild. Los cogs viejos no tienen que saber de i18n.

Transparent localization. main.py patches send/response so legacy cogs get translated embeds without knowing about i18n.

IA con recambio. utils/gemini_client.py prueba varios modelos y varias claves; si una da 429, la enfría y sigue. El chatbot elige proveedor según complejidad, no un SDK único.

IA with failover. Gemini client rotates models and keys; 429 cools that key. The chatbot routes by complexity across a provider pool.

Tickets full-stack. Cada mensaje se guarda en SQLite y el panel lo lee. Si el guild tiene canal de transcripciones, se replica a Discord. El HTML de transcript se sirve en /tickets/{id}/transcript.

Full-stack tickets. Every message is in SQLite for the dashboard; optional Discord transcript channel; HTML at /tickets/{id}/transcript.

Operación

Secretos solo en .env (token, OAuth client secret, claves de IA, Stripe). El repo público lleva .env.example vacío. La SQLite y las plantillas YAML de import no se publican. Healthchecks independientes bot/API. nginx termina TLS en dabot.davito.es y hace proxy a 127.0.0.1:8090.

Secrets live in .env only. Public repo has an empty example file. SQLite and import YAML stay off git. Bot and API have separate healthchecks. nginx TLS-terminates dabot.davito.es to localhost:8090.
